# 早餐店遊戲・規格（SPEC）

你要幫一間真的早餐店做一款手機小遊戲：「【店名】・早餐店打工」。客人從店家的 LINE 官方帳號點連結進來，直接在 LINE 裡玩，用 LINE 身分登入，成績上排行榜。

**玩法、數字、手感要跟範本 `reference/zaocan.html` 一模一樣**。這是一款已經上線、調過很多輪的遊戲（另一個網站「丼步喱」的「早餐・煎」）。你的工作是把它**搬出來變成獨立的一款**、換上這間店的招牌、接上 LINE 和排行榜，**不是重新設計**。動手前先完整讀過 `reference/zaocan.html` 和 `reference/zaocan.md`。下面列的規則和數字都是從範本整理出來的，跟範本有出入時以範本為準，並告訴我哪裡不一樣。

### 一、技術限制

- 純靜態 HTML，沒有建置工具，跟範本一樣：一頁 `index.html`，頁面專屬的 CSS、JS 寫在檔案裡，共用的放 `assets/`。用 GitHub Pages 發布（LIFF 一定要 HTTPS，GitHub Pages 本身就是）。
- 後端用 Google Apps Script Web App ＋ Google Sheet（程式備份在 `apps-script/Code.gs`，我自己貼去 Apps Script 部署，你沒辦法代為部署）。
- 介面全部繁體中文（`lang="zh-TW"`）。說明文件、版本紀錄也用繁體中文寫，我看不懂英文。
- 改了 `assets/` 裡的檔案，所有載入它的地方網址後面 `?v=日期` 要一起換新（LINE 內建瀏覽器和 GitHub Pages 都會快取舊檔）。

### 二、從範本拿掉、換掉的東西

範本是丼步喱網站的一部分，有很多那個網站才有的東西，要拿掉或換掉：

| 範本裡的 | 這一款怎麼做 |
| --- | --- |
| `wallet.js`（丼步喱的共用錢包，很多款遊戲共用） | 換成這款**自己的錢包**：只記這款遊戲賺的遊戲幣和店面升級，登入 LINE 後存在後端、跟著帳號走；沒登入只存在手機 `localStorage` |
| `line.js`（丼步喱的 LINE 登入） | 改用 LIFF SDK（見第五節） |
| `theme.css`／`theme.js`、夜間模式、晝夜切換鈕、侘寂配色、導覽列 | 都不要。配色換成店家的：主色【店家主色，預設 `#d9822b` 暖橘】、底色【預設 `#fff8ef` 奶油白】、文字【預設 `#3a2a1e` 深咖啡】。提示訊息自己做一個小膠囊（`showToast()`），不用瀏覽器的 `alert`／`confirm` |
| 「大橋頭麥克早餐店」、老闆是雞塊、日報上的浣熊老闆頭像 `zaocan-boss.jpg` | 店名【店名】；老闆頭像用【店家給的老闆照片或 logo，放 `assets/boss.jpg`】，載不到就畫一個簡單的廚師帽圖示 |
| 四位熟面孔（茱莉鴨、伊藤開晴、前夫、坐洗部的狗）：丼步喱的梗 | 保留「熟面孔」機制和數字，換成這間店的人物【店家想放的熟客，沒給就用下面的預設】：<br>・**愛吃半熟蛋的阿嬤**（6%，耐心 ×1.5，一定點半熟荷包蛋，一半機會加大冰紅）<br>・**刮刮樂大叔**（6%，用刮刮樂付小費：35% 刮中 $300，沒中就沒小費）<br>・**說要記帳的老鄰居**（4%，餐錢沒收到，但老闆另外補貼 $150「辛苦了」）<br>・**門口的狗狗**（5%，只點培根 1～2 份，耐心 ×0.75）<br>台詞照範本的語氣重寫，不要提到丼步喱的角色 |
| 明細最後一列「工資調漲」「主人加薪」（RAISE ×3） | 保留 ×3 和計算方式（等第照 ×3 之前的錢算），這一列改叫「老闆加碼」，說明「合計多 200%」 |
| 老闆台詞、等第台詞裡的雞塊、27 樓等梗 | 改成一般早餐店的說法，例如滿：「客滿，老闆請你喝大冰奶。」 |
| `zaocanLog` 送到丼步喱後端、丼步喱排行榜 | 換成這款自己的後端和排行榜（第六節） |
| 會員中心入口、「用 LINE 登入」按鈕 | 不需要；從 LIFF 進來就已經登入（第五節） |
| 專屬道具「全店六折」 | 拿掉 |

**菜單**：預設照範本的八樣（下面第三節）。如果店家要換成自己店裡的品項【店家菜單】，只換名字和畫法，煎的秒數、價錢、規則照範本對應的那一樣。

### 三、玩法規格（照範本，全部數字都要一樣）

**畫面**：畫布 360×440 固定座標，用 CSS 縮放到螢幕寬。上到下：
- 最上面：招牌和剩餘時間（左上）、目前賺的錢（右上）。畫布上面一行老闆的話＋右上出餐數，**固定兩行高**（字數變了畫布才不會上下跳、手指點偏）。
- **櫃台**：最多三位客人（x = 60／180／300）。客人頭上是**想法泡泡**，畫他想吃的東西的小圖：荷包蛋寫「半熟／全熟」，送到的打勾變淡，等太久泡泡會晃。櫃台上是**等待條**：綠 → 黃 → 紅，見底客人就氣走。
- 中間：**保溫台**（預設放 5 份）和右邊垃圾桶。
- 下面左邊：**鐵板**四格；右邊：**飲料機**（三桶：奶茶、紅茶、豆漿紅茶）和杯子。奶茶和豆漿紅茶顏色很像，杯子上印「奶」「豆」。
- 畫布下面：五個食材按鈕、三個**按住**倒飲料的按鈕（按鈕上寫價錢）。

**一場**：75 秒。**第一下放食材或倒飲料才開始計時**，在那之前第一位客人不會等到生氣。

**菜單**（`t1` 第一面幾秒熟、`t2` 翻面後幾秒熟）：

| 品項 | 價錢 | t1 | t2 | 備註 |
| --- | --- | --- | --- | --- |
| 荷包蛋 | $80 | 2.4 | 2.2 | 客人指定半熟或全熟 |
| 培根 | $90 | 1.9 | 1.9 | |
| 蘿蔔糕 | $105 | 3.0 | 2.6 | |
| 蛋餅 | $135 | 2.6 | 2.0 | 熟了要「捲」 |
| 鐵板麵 | $160 | 4.2 | — | 不用翻 |
| 大冰奶 | $90 | | | 飲料 |
| 大冰紅 | $70 | | | 飲料 |
| 豆漿紅茶 | $80 | | | 飲料 |

**煎**：
- 熟度 = 這一面煎了幾秒 ÷ 這一面要幾秒。熟度到 1 出現「翻」或「好」；到 **1.7 焦掉**（每一面都是），點一下丟掉、扣 $15。
- 熟度條上：白線是可以翻／夾的地方、綠色是剛好；荷包蛋翻面後 0.5～1 是黃色「半熟」、1 以上綠色「全熟」。
- 點第一面還沒熟的：食物抖一下、不能翻。熟了點一下就翻面。
- 翻面後（或鐵板麵）熟了點一下就夾到保溫台。荷包蛋翻面後熟度 0.5 就能夾：0.5～1 是半熟、1 以上是全熟。
- **捲蛋餅**：翻面熟了以後要在蛋餅上**橫著滑一下**。滑的速度在 120～700（畫布 px／秒），而且夠直（垂直位移小於水平的 0.7 倍），就是「捲得漂亮」；太快寫「太快，捲歪了」。**用點的也會捲，但一定算捲歪**，飄字「捲歪了・用滑的才漂亮」（以前點了不會夾，玩家以為卡住，一直點到焦掉）。
- 鐵板滿了：提示「煎台滿了」、食材按鈕抖一下。

**倒飲料**：
- 按住倒，1.4 秒倒滿（熟度 1.0）。放開時 0.7 以上算一杯，0.85 以上是「剛好」，0.7～0.85 是「少了一點」。不到 0.7 可以再按著補。
- 超過 1.02 滿出來：扣 $10、整杯倒掉，老闆說話。
- 杯子裡已經有一種時，不能倒另一種（提示「杯子裡是 XX，先倒完它」）。
- 倒好的杯子保溫台有空位就自己進保溫台，沒空就在機器上等。

**保溫台和送餐**：
- 保溫台滿了夾不起來時，**畫布上**要飄「保溫台滿了」、保溫台閃紅框。不要只寫在畫布下面的提示，手機上看不到。
- 點保溫台上的東西：只有一位客人要，就直接送；好幾位要，就先選起來再點客人。也可以直接拖給客人，或拖到垃圾桶丟掉。沒人要的會提示可以留著或丟掉。
- 送錯（例如荷包蛋熟度不對）：客人說「我要半熟的」／「我沒點這個」，記一次送錯。
- 點好幾樣的客人，每拿到一樣（還沒送齊）就**多等 6 秒**（不超過一開始的耐心），飄綠字「多等 N 秒」，一半機會說一句「好，還有呢？」這類的話。

**客人**：
- 一開始三個位子分別在第 0、4、9 秒來第一位（第 0 秒那位在開始前就站著）。客人走了以後，下一位隔 `隨機(1.0～3.0) × (1 − 0.4 × 進度)` 秒來（進度 = 經過秒數 ÷ 75）。剩不到 5 秒不再來新客人。
- 一般客人五種，耐心倍率不同：學生 0.85、上班族 0.9、阿伯 1.2、阿姨 1.1、工人 1.0。每種有自己的招呼、謝謝、生氣台詞（照範本）。長相隨機：膚色、髮色、衣服顏色、髮型（阿伯是光頭）。
- 熟面孔照第二節的機率，同一位熟面孔不會同時來兩個，來的時候有開門的音效。
- **點餐**：食物權重 荷包蛋 0.25、蛋餅 0.22、培根 0.15、蘿蔔糕 0.15、鐵板麵 0.13。點幾樣 = 1 ＋（機率 0.4＋0.35×進度 多一樣）＋（機率 0.08＋0.3×進度 再多一樣）。荷包蛋一半半熟、一半全熟。55% 加一杯飲料（大冰奶 45%、大冰紅 27%、豆漿紅茶 28%）。
- **耐心**（秒）=（18 ＋ 8 × 點幾樣）× 耐心倍率 ×（1 − 0.12 × 進度）× 隨機(0.92～1.08)。

**算錢**：
- 客人點的**全部送齊**才付錢：菜單價 ＋ 小費。小費 = 這一單 × 0.4 × 剩下的耐心比例，四捨五入到 5 元（送得越快給越多，最多四成）。
- 捲得漂亮的蛋餅、倒剛好的飲料，每份另外 +$30。
- 氣走一位扣 $80；焦掉一份扣 $15；打翻一杯扣 $10。
- 刮刮樂大叔、記帳老鄰居照第二節算，他們不給一般小費。
- 合計 ×3（「老闆加碼」那一列）。工資不到 $100 給 $100 保底出勤費。
- **明細每一列加起來一定要等於合計**。改價錢、加新的賺錢方式時，明細和合計兩邊一起改。
- **等第**（照 ×3 之前的錢算）：滿 $5,600、旺 $4,000、好 $2,700、慢 $1,300，以下是焦。

**打烊**：
- 響鈴，老闆說今天跑了幾位客人（或「一個都沒跑掉」）。
- 結果區：工資大字、等第一句話、出餐幾位幾份、氣走幾位、明細（名稱、數量、金額、一行小字說明怎麼算）。
- 產生「【店名】早餐店日報」圖片：老闆頭像、日期、工資、等第、明細、【店家地址或 LINE 官方帳號 ID，讓分享出去的人找得到店】。
- 存圖片用 `saveimg.js` 的做法：能分享檔案就叫分享選單；**在 LINE 內建瀏覽器裡下載連結按了沒反應**（安卓回報過），改成全螢幕放大圖片，請玩家長按存或截圖。按鈕字照環境換：「分享早餐店日報」／「存早餐店日報圖片」／「下載早餐店日報」。
- 最好的一天存在手機，沒開店時右上角顯示最好的一天，開店中顯示「出餐／氣走」。

**音效和震動**：照範本（煎的滋滋聲、翻面、夾起、倒、送出、氣走、打翻、最後 5 秒倒數、打烊鈴）。氣走時手機震動。

### 四、店面升級（照範本）

打烊後可以用這款自己錢包的遊戲幣買升級，等級只升不降。標題右上角一顆「店面」按鈕，結果區一顆「拿薪水升級店面」，打開底部面板；開店中不能開。按鈕放標題右上角，是因為多一行會把倒飲料的按鈕擠出手機畫面。

| 升級 | 等級和價錢 | 效果 |
| --- | --- | --- |
| 爐口 | $30,000／$90,000 | 鐵板 5／6 格（變成三列，第五格時第六格寫「還沒開」） |
| 保溫燈 | $15,000／$45,000 | 保溫台 6／7 份 |
| 自動翻面鏟 | $60,000 | 第一面熟度到 1.08 自動翻 |
| 不沾鐵板 | $10,000／$30,000／$80,000 | 焦的熟度 2.0／2.3／2.7（原本 1.7） |
| 招牌 | $20,000／$50,000／$100,000 | 賣價多 10%／20%／30%，明細多一列「招牌加價」，小費和記帳也照加價後算 |
| 大出水口 | $10,000／$30,000 | 倒滿一杯 1.0／0.75 秒 |
| 定量杯 | $15,000／$60,000 | 一級：「剛好」從 0.75 開始、倒到 1 自己停；二級：**點一下**自己倒到 0.93 停，手可以去顧鐵板 |
| 飲料輸送帶 | $40,000 | 倒好的飲料直接送給點它、等最久的客人，不佔保溫台 |

每項升級在畫面上都看得出來（範本有畫法：招牌紅底→木頭→燈箱→金字、保溫台暖黃、出水口變粗、刻度杯、輸送帶等）。

### 五、LINE 登入（LIFF）

- 店家在 LINE Developers 的**同一個 Provider** 下開一個 LINE Login channel，建 LIFF app（尺寸 Full、Endpoint 是 GitHub Pages 網址、scope `profile openid`），LIFF ID 寫在 `assets/config.js`。【LIFF ID 由店家提供】
- 店家 LINE 官方帳號的圖文選單或訊息放 `https://liff.line.me/【LIFF ID】`，客人點了就在 LINE 裡開遊戲。
- 頁面一開就 `liff.init()`。在 LINE 裡已經登入就直接拿 `liff.getProfile()`（顯示名稱、大頭貼）；在 LINE 外面打開（電腦、一般瀏覽器）可以玩，但成績不上榜，結果區放一顆「用 LINE 登入上排行榜」。
- 送成績時帶 `liff.getIDToken()`，**後端要驗證**（POST 到 `https://api.line.me/oauth2/v2.1/verify`，帶 `id_token` 和 `client_id`＝channel ID），驗過才信任裡面的使用者 ID。不要相信前端自己送來的使用者 ID 或名字。
- 個資只存最少的：LINE 使用者 ID、顯示名稱、大頭貼網址。不要電話、不要 Email。頁面底下放一句「排行榜只顯示你的 LINE 名稱和大頭貼」。

### 六、排行榜和後端

**Sheet 分頁**：
- `Players`：使用者 ID、名稱、大頭貼、遊戲幣、升級等級（JSON）、升級花了多少、累積工資、玩了幾場、最高一天、出餐最多、第一次玩、最後一次玩。
- `Rounds`：每一場一列。欄位刻意收齊，之後要做別的榜才有資料：時間、使用者 ID、工資、等第、出餐幾位、幾份、氣走、送錯、焦、打翻、丟掉、捲漂亮／捲歪、倒剛好／少一點、半熟／全熟蛋、最快出餐（毫秒）、平均等多久、每種賣幾份、熟面孔來了幾次、當時的升級等級。

**API**（`doPost`，JSON 進 JSON 出）：
- `start`：開一場，回一張一次性的開場單（存在 `CacheService`，記使用者和開始時間）。
- `finish`：帶開場單、ID token、這一場的紀錄。後端檢查：開場單有效而且沒用過、從開場到現在至少 75 秒、工資不超過合理上限（用第八節的模擬算一個上限，例如全升級最快機器人的 1.5 倍）、同一人一分鐘最多交一場。過了才記錄、加錢、更新最高紀錄；沒過就記一列「可疑」，不上榜，前端照樣讓他看結果。
- `buy`：買升級，後端扣錢、檢查等級和價錢（價錢表後端也寫一份，不信任前端送來的價錢）。
- `me`：讀自己的錢包和升級。
- `board`：讀排行榜。
- 多人同時寫 Sheet 要用 `LockService` 排隊。

**排行榜**（遊戲裡一個分頁或底部面板）：
- 兩個榜：**一天賺最多**（單場最高工資）、**出餐最多**（單場出餐最多位，一樣多比氣走少）。可以再加【店家想要的週榜／月榜】。
- 列前 50 名：名次、大頭貼、名稱、成績；自己那列標「我」，不在前 50 名就補在最後。前三名做得醒目一點（金、銀、銅）。
- 用排程每 5 分鐘先算好整份榜存快取，打開只讀現成的；頁面寫「排行榜每五分鐘更新一次」。
- 【如果店家要給前幾名送餐點優惠：排行榜和兌換方式另外討論；遊戲幣本身不能拿來換東西、也不能用錢買】

### 七、手機上的注意事項（範本踩過的坑，照做）

- 以手機 375px 寬、觸控為主。不能出現水平捲動；長按要擋掉系統選單和文字選取；倒飲料的按鈕要用 `pointerdown`／`pointerup`（含 `pointercancel`、手指滑出按鈕）判斷放開。
- 開店中，任何浮在畫面角落的按鈕都要藏起來，不能蓋到倒飲料的按鈕（範本的晝夜鈕就蓋住過「大冰奶」，按了倒不出來）。
- 動畫迴圈：`frame()` 最後叫 `nextFrame()`。畫布整個捲出畫面就停（`IntersectionObserver`），捲回來重設時間。沒在玩的時候（標題、結果畫面）每秒只畫約 20 張（`setTimeout(…, 34)` 再 `requestAnimationFrame`），剛打烊的 2.5 秒照常 60 張給結算動畫。dt 上限 50ms。不要在 `frame()` 裡直接 `requestAnimationFrame(frame)`，手機會燙。
- 畫布大小沒變就不要重設 `cv.width`／`cv.height`。手機捲動時網址列伸縮會一直觸發 `resize`，重設會清空畫布、狂閃。
- 分享預覽：`<head>` 放 `description` 和 Open Graph（`og:title`、`og:description`、`og:image` 用完整網址），圖片【店家提供的正方形圖，1200×1200】。沒寫的話 LINE 會抓畫面上奇怪的字當介紹；換圖時 `og:image` 後面的 `?v=` 加一。
- 字型：Noto Sans TC（Google Fonts，前面加兩行 `preconnect`）。

### 八、驗收

1. 寫一個模擬機器人（Node 跑 `tools/sim.js`，直接用遊戲的規則程式碼），機器人每 0.6／0.45／0.32／0.24 秒做一個動作、倒飲料時不能做別的，各跑幾百場。沒升級時平均工資（×3 之前）應該在範本記錄的附近：約 $2,250／$3,880／$5,610／$6,410；全升級約 $5,710／$7,820／$9,660／$10,450。差太多代表規則抄錯了，先找出哪裡不一樣。
2. 手機實測清單：在 LINE 裡從連結打開、第一位客人在開始前不會氣走、捲蛋餅滑的和點的、按住倒飲料放開／補倒／滿出來、保溫台滿了的提示看得到、拖到客人和垃圾桶、送錯荷包蛋、打烊明細加總等於合計、在 LINE 裡存日報圖片、排行榜出現自己、在 LINE 外面打開不會壞。
3. 交付：`index.html`、`assets/`、`apps-script/Code.gs`、`docs/SETUP.md`（店家和我要怎麼設定 LINE Developers、LIFF、圖文選單、Apps Script 部署、Sheet，一步一步寫，用繁體中文）、`changelog.md`（每次改完在最後面加一段：日期時間、改了什麼、要不要重新部署後端）。

### 九、不要做的事

- 不要改玩法、數字、手感（除非我說）。要改的話先問。
- 不要用真錢買遊戲幣，遊戲幣也不能換現金或餐點（排行榜獎勵另外處理）。頁尾寫一句「遊戲幣只在遊戲裡用，不能儲值，也不能換成現金或餐點」。
- 不要把任何密碼、channel secret 寫進前端或 repo（repo 是公開的）。要用的放 Apps Script 的指令碼屬性。
- 不要讓 LINE bot 的 webhook 接到這個遊戲後端，遊戲只是一個 LIFF 網頁。

## 開工前要問朋友的事

1. **店名**、要放在日報上的**地址或 LINE 官方帳號 ID**。
2. **配色**和 **logo／老闆照片**（日報上的老闆頭像）、分享預覽用的正方形圖。
3. **菜單**要照丼步喱的八樣，還是換成店裡真的品項（最多換名字，玩法對應不變）。
4. **熟面孔**要不要換成店裡真實的熟客梗（用預設的阿嬤、刮刮樂大叔、記帳老鄰居、狗狗也可以）。
5. **LINE 官方帳號**：誰有 LINE Developers 的權限，能開 LINE Login channel 和 LIFF。
6. **Google 帳號**：Apps Script 和 Sheet 要放在誰的帳號底下（建議放店家的，資料是他的客人）。
7. **排行榜要不要送獎勵**（例如每月第一名送一杯飲料）。要送的話，防作弊要做嚴一點，兌換方式也要另外想。
8. **店面升級要不要保留**。保留的話，玩越久的人升級越多、越容易上榜，對新客人不太公平；也可以讓排行榜只比「沒升級」的成績，或分開兩個榜。
